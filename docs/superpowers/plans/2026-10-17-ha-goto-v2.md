# ha-goto v2.0.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the `goto_sms` HACS integration on the `gotoconnect` PyPI library: fully async, Application Credentials OAuth with zero re-auth for existing users, the existing SMS surfaces unchanged, plus a new `goto_sms.call_tts` voice service — on a branch, never tagged by this plan.

**Architecture:** The integration becomes a thin HA adapter: HA's `OAuth2Session` owns tokens and feeds `GoToMessaging` as a token provider; a custom `AuthImplementation` does GoTo's Basic-auth token exchange; `async_migrate_entry` (VERSION 1→2) imports the old entry's client credentials into Application Credentials and rewrites stored tokens, so existing installs upgrade in place. Voice renders TTS via HA's `tts.async_create_stream` (8 kHz mono WAV, core transcodes) and hands bytes to `GoToVoice`. The hand-rolled `oauth.py` dies.

**Tech Stack:** Python (HA custom integration), `gotoconnect==0.1.0` (PyPI), `homeassistant.helpers.config_entry_oauth2_flow`, `pytest-homeassistant-custom-component`, hassfest + HACS Action in CI.

**Spec:** `/home/taylor/dev/ha-goto/docs/superpowers/specs/2026-10-17-goto-connect-voice-and-core-design.md` (as amended: domain STAYS `goto_sms` through the HACS phase).
